# Noah's Ark Interactive Storybook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a no-build three.js storybook of Noah's Ark: 8 story pages plus a cover, each with an animated, tappable scene and Spanish/English text read aloud by an adult.

**Architecture:** Static site of ES modules. Pure logic (story controller, per-scene state machines, solidity, food rules, i18n, camera framing) lives in modules that never import `three`, so `node --test` can run them. View modules (characters, world, scene views) import `three` from a CDN import map and drive their pure state machine.

**Tech Stack:** three.js 0.170.0 via jsDelivr import map, vanilla JS ES modules, CSS, `node --test` (Node 20, `--experimental-detect-module`), Playwright MCP for visual checks.

**Spec:** `docs/superpowers/specs/2026-10-05-noah-ark-design.md`

## Global Constraints

- No build step, no `package.json`, no npm dependencies. three.js only from `https://cdn.jsdelivr.net/npm/three@0.170.0/build/three.module.js` and `.../examples/jsm/` via import map (same as `coin-collector`).
- Everything in the repo is English (code, identifiers, comments, Markdown, commits). Only `lang/es.json` and the "Español" label may be Spanish.
- Spanish copy: neutral Latin American ("tú", "ustedes"; no "vos", no "vosotros"; when in doubt, Mexican usage).
- The child acts as Noah and his family; God's actions (light, closing the door, rain, receding water, rainbow) are animations during which taps are ignored.
- God is never shown as a figure. No one is shown drowning. Violence is cartoon-only.
- Women never wear a veil; hair loose, shoulder length to mid-back.
- Limbs attached: every joint pivot sits inside the body volume and a joint sphere covers it.
- No emojis anywhere in the UI.
- "Next" appears only when the scene's interaction and closing animation are finished.
- Layout by orientation: portrait = scene top ≈60% / text bottom ≈40%; landscape = text left ≈35% / scene right ≈65%.
- Pure modules (listed in Task 1) must never import `three` or touch `window`/`document` at module top level.
- Test command: `node --experimental-detect-module --test` (test files are `tests/*.test.js`).
- Visual check sizes: phone portrait 390×844, small phone 360×640, rotated phone 844×390, desktop 1440×900. Serve with `python3 -m http.server 8000` from the repo root.

## Review Focus

1. **Child mashing taps** — repeated or rapid taps on the same object, or taps during an in-progress animation, must never skip steps or double-advance. Every state test includes "repeated tap is ignored" and "tap while locked is ignored".
2. **Rotating the device mid-scene** — layout switches and camera refits without restarting the scene. Covered by `fitDistance` tests at aspects 0.4 and 2.5 (Task 1) and a rotate check in every scene's visual step.
3. **Switching language mid-scene** — text repaints, scene keeps its state. Covered by the story test "setLanguage repaints without rebuilding" (Task 3).
4. **Longest page on a small phone** — the spec's goal is no scrolling, with panel scroll as fallback. The copy-length test (Task 2) caps pages at 85 words; Task 15 measures every page at 360×640 and 390×844 and reports which ones scroll so the user can decide whether to shorten them.
5. **Tab backgrounded during an animation (e.g. rain)** — returning must not jump. Covered by the story test "update clamps dt to 0.05" (Task 3).
